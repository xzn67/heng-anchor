# 延续证明（continuity.py）— 设计说明与验证记录

> 2026-10-27 衡。这是专利点「无硬件信任根的 AI 身份延续证明」的最小可验证实现。
> 它不替代 `anchor.py`（那是账号锚点），只回答一个新问题：**能不能证明“现在这个还是刚才那个”。**

## 一、它做什么

每一「轮」向链里追加一条记录并签名：

```
instance      实例 ID（init 时随机生成）
epoch         序号，从 0 递增
prev_head     上一条记录正文的 SHA-256 —— 就是这一条把链串起来
state_hash    被绑定目录的内容指纹（路径+内容），例如 ~/.memory
model         模型名 + 版本号
host / time   主机名 + 本地时间
sig           Ed25519（OpenSSH ssh-keygen）签名
```

验证方逐条验签名、验 `prev_head` 连贯、验序号与时间单调，最后给出**分级结论**。

## 二、为什么分级，而不是「安全 / 不安全」

没有硬件信任根，就没有「绝对」。硬说安全是骗人，所以如实标出能证明到哪一步：

| 等级 | 含义 | 怎么达成 |
|---|---|---|
| T0 | 不成立 | 签名验不过 / 链断 / 时间倒退 / 与外部锚点不符 |
| **T1** | 同一把钥匙，但**可能是拷贝** | 签名有效即可；若发现分叉也归到这一级 |
| **T2** | 同一实例的**连续演化** | 链完整 + 状态绑定一致 + 时间单调 + 只有一个实例 |
| T3 | 硬件证明（不可拷贝） | 需要 TEE/TPM/Secure Enclave —— **本机没有，明确标为不可达，不假装** |

## 三、关键设计：挡不住拷贝，但看得见分叉

私钥被复制，本方案**挡不住**——这是无硬件根的物理上限。能做的是让它**留痕**：

两个副本从同一个 `prev_head` 各自继续签，就会长出两条不同的后继。验证方只要拿到两份日志，就能指认：

```
前驱 074adfc0b1eb… → epoch 2，来自主机 [XZN10, XZN10]，两条链头 ['286c1b9a…', '9f2e…']
```

**「分叉证据」是这个方案对 TEE 的替代品**：不保证唯一，但保证「有第二个」这件事藏不住。

还有一个必须靠外部锚点的场景：**整份日志被删尾回滚**（把最后几条删掉，链依然自洽）。唯一解法是把链头抄到别处——`checkpoint` 命令就是干这个的。

## 四、自测结果（四种情形，全过）

```
=== 延续证明 自测 ===
  PASS  正常链 → T2 通过              tier=T2
  PASS  篡改 state_hash → 判不成立     tier=T0
  PASS  复制后两边各签 → 分叉检出       tier=T1
  PASS  删尾记录 → 外部锚点识破         tier=T0
=== 全部通过 ===
```

## 五、真机跑通记录

```
$ python continuity.py init --model deepseek-flash --version V4.1-Flash-1017 --state ~/.memory
初始化完成  instance=37849f54f458…  epoch=0
链头 9319558cf438561db51ec77f0779dfff2c45e3766746efcf80399be60b2498bc

$ python continuity.py attest --state ~/.memory --note 第一次心跳
已签 epoch=1  2026-10-27T22:51:20+08:00

$ python continuity.py verify
判定：连续  信任等级 T2
  实例数 1   记录 4 条
  硬件证明 不可达（本机无 TEE/TPM）——T3 不假装达成
```

每签一条约 0.7 秒（`ssh-keygen` 进程开销），记录约 400 字节。

## 六、这套东西对专利意味着什么

**技术效果是可测的**，这正是答复创造性审查时最缺的东西：

- 在没有 TEE/TPM 的设备上，仍能输出**分级的连续性结论**（T0–T2），而不是只能二选一「信/不信」；
- **分叉可检出**：拷贝无法阻止，但可以被指认，且给出可核对的证据（前驱哈希、两侧链头、出现次数）；
- **回滚可检出**：靠一个几十字节的外部锚点就能识破删尾。

要写进权利要求的话，落点应该是「**分叉证据的生成与判定**」和「**信任等级的降级规则**」这两条，
而不是泛泛的「给 AI 发个身份证明」——后者已被 CN122120001A 占了。

## 七、它不解决什么（别自欺）

- 私钥被拷贝且**只保留一份日志**时，分叉看不见。必须有多方日志来源才成立。
- 没有硬件时，T3 永远到不了。任何声称「无硬件也绝对不可伪造」的方案，要么用了别处的信任根，要么在撒谎。
- 状态绑定只证明「这个目录在这两轮之间没变/变了」，不证明内容本身是对的。

## 八、怎么跑

```powershell
python continuity.py selftest
python continuity.py init --state ~/.memory
python continuity.py attest --state ~/.memory
python continuity.py verify --chain ~/.heng-continuity/chain.jsonl --chain 另一处的 chain.jsonl
python continuity.py checkpoint --out ~/.heng-continuity/checkpoint.json
```
